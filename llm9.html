1. The Stage We Are At

Up to this point, we have built a very important mental picture:

  • The training corpus secretly defines a probability distribution pdata(context | center) through how often word pairs appear.
  • Our model (using scores → exponentials → softmax) defines its own probability distribution pmodel(context | center).

No matter how we say it in words, the core goal is:

Make the model’s probability distribution look like the data’s probability distribution.

More concretely:

  • The data says things like: “When the center is love, the context my appears often, I and You appear sometimes, and some words almost never appear.”
  • The model, using W and C and softmax, also produces a probability distribution over all possible context words given a center.

Training is about pushing the model so that:

pmodel(context | center) ≈ pdata(context | center).

To do this, we need a way to measure how good or how bad a particular prediction is. This will become our loss function. We will build it from one simple but powerful idea: the idea of surprise.

2. When Should a Model Be Rewarded or Punished?

Imagine our tiny universe of sentences again:

I love my dog.
I love my cat.
You love my dog.
You love my cat.

From this corpus, we know that when the center word is love, contexts like I, You, and my are common. So the data distribution pdata(context | love) puts a lot of weight on these.

Now suppose our model predicts:

  • pmodel(my | love) = 0.9

and the event we see in the training data is:

(love → my)

The model is not surprised at all. It basically said:

“I am 90% sure the context will be my.”

So when my actually appears, the model should receive very little punishment.

On the other hand, if the model had predicted:

  • pmodel(my | love) = 0.01

it is almost ruling out my as a possible context. When the event (love → my) appears in the data, the model should be:

extremely surprised and heavily punished.

So we want a numerical way to capture this feeling:

  • High predicted probability for the actual event → small penalty (low surprise).
  • Low predicted probability for the actual event → large penalty (high surprise).

This leads naturally to the idea of a surprise function.

3. Defining Surprise for a Single Event

Let’s focus on a single training event:

(center = love, context = my)

The model assigns some probability:

p = pmodel(my | love)

We want a function S(p) that measures the surprise of the model when this event occurs in the data. Intuitively, S(p) should satisfy:

  • If p is close to 1 (model was very confident) → surprise should be close to 0.
  • If p is moderate (e.g., 0.5) → surprise should be moderate.
  • If p is tiny (e.g., 0.001) → surprise should be very large.

So S(p) should:

  • be a decreasing function of p,
  • grow rapidly as p approaches 0,
  • give 0 when p = 1 (no surprise if you were certain and correct).

There is a very natural candidate that fits these properties:

S(p) = -log(p)

This is not a random choice. It is deeply connected to how probabilities behave and how we want penalties to accumulate. We will now look at this function in detail and see why it is such a good measure of surprise.

4. Seeing Surprise = –log(p) in Action

Let’s take some example probabilities p and compute the corresponding surprise values -log(p). To make things concrete, we will use the natural logarithm (log base e). The exact base is not important for intuition; it just scales the values.

Model probability p
(for the actual event)		 Surprise S(p) = -log(p) Intuitive interpretation
p = 0.99 −log(0.99) ≈ 0.010 Model was almost certain. Very little surprise.
p = 0.9 −log(0.9) ≈ 0.105 Model was quite confident. Low surprise.
p = 0.5 −log(0.5) ≈ 0.693 Model was unsure (50–50). Moderate surprise.
p = 0.1 −log(0.1) ≈ 2.302 Model thought event was unlikely. High surprise.
p = 0.01 −log(0.01) ≈ 4.605 Model almost ruled it out. Extremely high surprise.

This table shows exactly the behavior we want:

  • As p gets larger (the model believes more in the actual event), S(p) = -log(p) gets smaller.
  • As p gets smaller (the model almost rules out the actual event), S(p) grows very quickly.

In particular:

  • If p = 1, then -log(1) = 0 → zero surprise. The model was perfectly confident and correct.
  • As p → 0, -log(p) → ∞ → the model gets an almost infinite penalty for declaring the event “impossible” when it actually happens.
So -log(p) behaves exactly like a “surprise meter” for a single event.

5. Connecting Surprise to the Log Function

Now we can explicitly connect this to the log function itself.

The logarithm log(p) has the following properties when 0 < p ≤ 1:

  • log(1) = 0
  • log(p) is negative when 0 < p < 1
  • As p decreases towards 0, log(p) decreases towards -∞

If we multiply by -1, we flip the sign:

  • -log(1) = 0
  • -log(p) is positive when 0 < p < 1
  • As p decreases towards 0, -log(p) increases towards +∞

Graphically, you can imagine -log(p) as a curve that:

  • starts at 0 when p = 1,
  • rises gently as p goes down to 0.5,
  • rises sharply as p goes further down to 0.1, 0.01, and so on.

This is exactly how surprise should behave:

  • Being slightly wrong is okay → small penalty.
  • Being wildly wrong (assigning tiny probability to something that happens) is not okay → huge penalty.
-log(p) is not just a random function we picked. It is the logarithm applied in a way that turns probabilities into a natural measure of surprise.

6. Surprise as the Building Block of Loss

For each training event (center, context), the model gives a probability p = pmodel(context | center). We now define the surprise of that event as:

surprise(center → context) = -log pmodel(context | center)

This single number captures:

  • How strongly the model believed in the actual event (through p).
  • How “shocked” the model should feel when this event is revealed by the data (through -log(p)).

Once we have this notion of surprise for individual events, we can aggregate it over many events in the training set and talk about the model’s average surprise on the data. That average surprise will become our loss: a single number that tells us how well the model is matching the data’s behavior.

The key insight is:

If the model assigns high probability to events that occur often in the data, its surprise values will be small. If the model assigns low probability to those events, its surprise values will be large.

By constructing surprise using the log function in this way, we get a clean, mathematically grounded way to turn probabilities into a meaningful penalty. This will form the core of how we define and minimize our loss.
