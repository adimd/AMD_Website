In Blog 1, we looked at unsupervised learning through a storage lens. We asked a simple question. If I have a dataset, what is the most sensible way to store it so that I can reconstruct it later.

In that first post, everything was friendly. All points lay exactly on a line, so compression came almost for free. You could store the direction of the line and store one scalar per point. Reconstruction was exact because the data truly lived on that structure.

This post is where we make the setup slightly more realistic.

We keep the same idea of representing data using a line, but we introduce one point that is not on the line. That one point is enough to force a choice. Either we insist on exact reconstruction and slowly lose the benefits of compression, or we accept approximation and make the approximation principled.

A small dataset that behaves nicely

Let us start with the same kind of small dataset as before. Four points in two dimensions.

\[ x_1 = [-7, -14], \quad x_2 = [2.5, 5], \quad x_3 = [0.5, 1], \quad x_4 = [0, 0] \]

If you plot these points, they lie on the same line. In fact, each point satisfies \(y = 2x\).

Figure 1 — Four points in two dimensions lying exactly on the line \(y = 2x\).

If you store this dataset naively, how many numbers do you need?

Two coordinates per point, four points total.

\[ \text{Naive storage} = 4 \times 2 = 8 \text{ numbers} \]

Now we use the structure. A line through the origin can be described by a direction vector. One convenient choice here is:

\[ w = [1, 2] \]

Every point on this line can be written as a scalar multiple of \(w\). That means each point can be represented using just one number \(c\) such that:

\[ x = c\,w \]

For example:

\[ [-7, -14] = -7 \,[1,2], \quad [2.5, 5] = 2.5 \,[1,2], \quad [0.5, 1] = 0.5 \,[1,2], \quad [0,0] = 0 \,[1,2] \]

Figure 2 — The same dataset expressed as scalar multiples of a single direction vector \(w = [1,2]\).

From a storage point of view, this gives a different representation. Instead of storing four two dimensional points, we store one direction vector and four scalars.

\[ \text{Structured storage} = 2 + 4 = 6 \text{ numbers} \]

Perfect Compression

We went from 8 numbers to 6 numbers with zero information loss.

In this particular dataset, this representation is lossless because the data lies exactly on the line. We can reconstruct each point exactly using \(c_i w\).

Now introduce one point that does not lie on the line

Now add one more data point:

\[ x_5 = [3, 8] \]

If you compare it with the line \(y = 2x\), the point \([3,8]\) does not fit. If it were on the line, its y coordinate would have been 6, not 8.

This is a small mismatch. But it changes the representation problem completely.

Figure 3 — A new point that does not lie on the line. The dataset is now only approximately line-structured.

If you insist on exact reconstruction, you cannot represent \([3,8]\) as \(c[1,2]\). So you would need to store extra information that captures how far the point is from the line.

The Storage Dilemma

Exact reconstruction: Store correction terms for every off-line point. Eventually this becomes as expensive as naive storage.

Approximate reconstruction: Accept controlled loss and preserve compression benefits.

This is the important practical issue. If many points are slightly off the line, you keep storing many correction terms. Over time, the representation starts to look like naive storage again.

So, if the goal is compression, exact reconstruction stops being a good default choice. The sensible choice becomes approximate reconstruction, but done in a controlled way.

The proxy idea

Once we accept approximation, we need a clear rule for what we will store.

The rule we will use is simple. For any point \(x\) that does not lie on the line, we replace it with a point on the line. That replacement point is the proxy.

Since the line is described by \(w\), every point on the line has the form \(c\,w\). So choosing a proxy is the same as choosing a value of \(c\).

\[ \hat{x}(c) = c\,w \]

If you change \(c\), the proxy point slides along the line. Different values of \(c\) give different candidate proxies.

Figure 4 — Candidate proxy points \(c\,w\) along the line for an off-line point \(x\).

Error as a vector and as a length

Once we choose a proxy point \(c\,w\), we can write the difference between the true point and the proxy. This difference is a vector.

\[ e(c) = x - c\,w \]

This vector tells us how much information we lose when we replace \(x\) by \(c\,w\). The direction of this vector shows where the proxy fails to match the true point. The length of this vector tells us how large the mismatch is.

Figure 5 — The error vector \(e(c) = x - c\,w\) drawn from the proxy point to the true point.

Now the goal becomes concrete. We want the proxy whose error vector has the smallest length.

To compute this efficiently, we minimize the squared length of the error. Squaring removes the square root and does not change which proxy is best.

\[ \min_c \; \|x - c\,w\|^2 \]

Why this turns into a quadratic minimization

Let us be very clear about what is changing and what is fixed.

The data point \(x\) is fixed. The direction \(w\) is fixed. The only quantity we are free to choose is the scalar \(c\).

Choosing a value of \(c\) places the proxy point \(c\,w\) at a specific location on the line. Changing \(c\) moves this proxy back and forth along the same line.

For each choice of \(c\), there is a corresponding error vector:

\[ e(c) = x - c\,w \]

The quality of the proxy is determined by the length of this error vector. To make the analysis simpler while preserving the same ordering of errors, we work with the squared length.

\[ f(c) = \|x - c\,w\|^2 \]

From Geometry to Algebra

We started with a geometric problem: find the best proxy on a line.

We converted it into an algebraic problem: minimize a function of one variable \(c\).

This is now an ordinary function of a single real variable \(c\). To understand its behavior, we expand it explicitly.

Using the identity \(\|a\|^2 = a^\top a\):

\[ f(c) = (x - c\,w)^\top (x - c\,w) \]

Expanding term by term gives:

\[ f(c) = x^\top x - 2c\,x^\top w + c^2\,w^\top w \]

Now look at this expression as a function of \(c\).

The first term \(x^\top x\) is constant. The second term \(-2c\,x^\top w\) varies linearly with \(c\). The third term \(c^2\,w^\top w\) varies quadratically with \(c\).

Since the coefficient of \(c^2\) is positive, the function curves upward and has a single minimum.

An upward curving quadratic has a single minimum. That minimum corresponds to the best possible placement of the proxy along the line.

To find this minimum, we differentiate \(f(c)\) with respect to \(c\) and set the derivative to zero.

\[ \frac{df}{dc} = -2x^\top w + 2c\,w^\top w \]

Setting this equal to zero gives:

\[ -2x^\top w + 2c\,w^\top w = 0 \]

Solving for \(c\), we obtain:

\[ c^* = \frac{x^\top w}{w^\top w} \]

The Optimal Proxy

This value of \(c^*\) gives the unique proxy point \(c^* w\) on the line that minimizes the reconstruction error.

The derivation makes the geometry explicit. The best proxy is found by sliding along the line until the squared distance to the data point is as small as possible.

Why we normalize the direction vector

Solving the minimization problem gives the optimal coefficient:

\[ c^\star = \frac{x^\top w}{w^\top w} \]

This expression already solves the problem of finding the best proxy for a fixed direction. But it also reveals a deeper issue.

The numerical value of \(c^\star\) depends on how long we choose \(w\) to be.

The denominator \(w^\top w\) is the squared length of the direction vector. This means the numerical value of \(c^\star\) depends on how long we choose \(w\) to be.

This dependence is problematic.

A direction vector is meant to describe orientation, not scale. The vectors \(w\), \(2w\), and \(0.5w\) all describe the same line through the origin.

However, if we replace \(w\) by \(2w\), the value of \(c^\star\) changes by a factor of four. If we replace \(w\) by \(0.5w\), the value of \(c^\star\) changes again.

The Scaling Problem

The vectors \(w\), \(2w\), and \(0.5w\) describe the same geometric line, but they produce different values of \(c^\star\).

This makes the coefficient \(c\) depend on an arbitrary scaling choice.

This means that the coefficient \(c\) no longer has a stable interpretation. Its value depends on an arbitrary scaling choice rather than on the geometry of the data.

From a representation point of view, this is unacceptable. We want the scalar \(c\) to measure how much of the point \(x\) lies in the chosen direction. That measurement should not depend on how we happened to scale the direction vector.

The simplest way to remove this ambiguity is to fix the length of \(w\). We do this by enforcing:

\[ \|w\| = 1 \]

With this constraint, the squared length \(w^\top w\) becomes equal to 1. The expression for the optimal coefficient simplifies immediately:

\[ c^\star = x^\top w \]

This form is important because it has a direct geometric meaning.

Since \(w\) has unit length, the inner product \(x^\top w\) measures the signed length of the projection of \(x\) onto the direction \(w\).

Larger values mean that \(x\) extends strongly in the direction \(w\). Smaller values mean weaker alignment. A value of zero means that \(x\) has no component along \(w\) at all.

The Power of Normalization

By setting \(\|w\| = 1\), we achieve three things:

1. Remove arbitrary scaling ambiguity

2. Give \(c\) a clear geometric interpretation as a projection length

3. Enable meaningful comparison of errors across different data points

Normalizing the direction vector therefore removes arbitrary scaling, gives the coefficient \(c\) a clear and consistent meaning, and prepares the ground for comparing projection errors across many data points.
