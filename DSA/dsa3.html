Pointers

The address is the thing. Everything else follows from that.

One new idea

In the last post you learned that a variable is bytes at an address. When you write int x = 42, the compiler picks an address — say 1000 — and stores 42 in the 4 bytes starting there. The name x is your label for that address. At runtime only the address exists.

There is exactly one new idea in this entire post. What if you had a variable whose value was not 42, but was the address 1000 itself? A variable that holds a location instead of data.

That is a pointer.

C
int  x = 42;    // a variable holding the value 42
int *p = &x;    // a variable holding the ADDRESS of x

p is a regular variable. It lives at its own address in memory. It takes up space just like x does. The only thing special about it is what its bytes represent: the address where x lives. On a 64-bit system a pointer is 8 bytes — enough to hold any address in a 64-bit address space. On your STM32 it is 4 bytes.

A pointer in memory
Hover either variable to inspect it
p is just a variable. Its value happens to be the address of x. That is all a pointer is.

Two operators — that is the whole language

There are exactly two operators for working with pointers. Understanding both completely is the entire skill.

The & operator — give me the address of something

C
int  x = 42;
int *p = &x;    // & means "the address of x"
                // p now holds whatever address x lives at

The & operator takes a variable and gives you the address where that variable lives. You have already used this — when you passed &x to printf with %p in the last post, that was the address-of operator.

The * operator — go to this address and read or write

C
int  x = 42;
int *p = &x;

printf("%d\n", *p);   // go to the address in p, read 4 bytes, print as int
                        // prints 42

*p = 100;              // go to the address in p, write 100 there
printf("%d\n", x);    // prints 100 — x changed because p pointed at it

This is called dereferencing. You are following the pointer to its destination. The * here does not mean multiply. It means "go to the address stored in this pointer and read or write what is there."

The reason x changed when you wrote to *p is that p holds the address of x. Writing to *p and writing to x are the same operation — they both reach the same bytes at the same address. p is not a copy of x. It is a direct window into x.

The three meanings of * in C

This is what trips everyone up early. The * symbol means three completely different things depending on where it appears.

C
int *p = &x;    // DECLARATION — "p is a pointer to int"
                // * is part of the type. Tells the compiler what p is.

*p = 100;       // DEREFERENCE — "go to the address in p and write"
                // * is an operator acting on p at runtime.

int c = a * b;  // MULTIPLICATION — completely unrelated

Same symbol. Three different things. Context is the only way to tell them apart. Once you see this clearly it never confuses you again.

Writing through a pointer
New value
Writing to *p changes x directly. They are the same address. There is no copy.

Why pointers exist at all

A reasonable question is: why bother? If you want to change x, just write to x directly. Three reasons explain why pointers are not optional.

Reason 1 — Functions cannot change your variables without them

In C, when you pass a variable to a function the function gets a copy. Changes inside the function do not touch the original.

C — pass by value, does not work
void try_to_change(int val) {
    val = 999;           // changes the local copy only
}

int main() {
    int x = 42;
    try_to_change(x);
    printf("%d\n", x);   // still 42
}
C — pass by address, works
void actually_change(int *ptr) {
    *ptr = 999;          // follows the pointer, changes the original
}

int main() {
    int x = 42;
    actually_change(&x);
    printf("%d\n", x);   // now 999
}

Reason 2 — Stack variables die when a function returns

If you want a function to create something that the caller can use, you have to allocate it on the heap and return a pointer to it. A pointer to a stack variable becomes a dangling pointer the moment the function returns — the memory is no longer yours and reading it is undefined behavior.

C — heap allocation survives the function return
int* create_array(int size) {
    int *arr = malloc(size * sizeof(int));
    for (int i = 0; i < size; i++)
        arr[i] = i * 2;
    return arr;    // heap memory — valid after return
}

int main() {
    int *data = create_array(5);
    printf("%d\n", data[2]);   // 4
    free(data);
}

Reason 3 — Every data structure requires them

A linked list is a chain of nodes where each node holds a pointer to the next. A tree is a node that holds pointers to its children. A graph is nodes holding pointers to neighbors. Without pointers you can only work with data that sits in a single contiguous block. Every non-trivial structure in this series is built from pointers connecting pieces of heap memory.

Pointer arithmetic

Now the part that unlocks arrays completely.

You know a pointer holds an address. What happens when you do math on that address?

C
int arr[5] = {10, 20, 30, 40, 50};
int *p = &arr[0];   // p points to the first element, say address 1000

p + 1;              // NOT address 1001. Address 1004.
p + 2;              // address 1008
p + 3;              // address 1012

When you add 1 to a pointer, C does not add 1 byte. It adds 1 times the size of whatever the pointer is pointing to. For an int *, adding 1 moves forward by 4 bytes. For a double *, adding 1 moves forward by 8 bytes. For a char *, adding 1 moves forward by 1 byte.

This is not a quirk. It is designed to match how arrays are laid out. Array elements sit at consecutive addresses spaced exactly sizeof(element) bytes apart. Pointer arithmetic scaled by type size means p + i always lands exactly on element i, regardless of the type.

Pointer arithmetic — moving through an array
p + 0 → addr 1000
Adding N to a pointer moves it forward by N elements, not N bytes. The type size is baked into the arithmetic.

Arrays are pointers — the full picture

Here is the insight that ties everything together. In C, the name of an array is just a pointer to its first element.

C
int arr[5] = {10, 20, 30, 40, 50};

printf("%p\n", arr);       // address of first element
printf("%p\n", &arr[0]);   // same address — identical

And because of that, array indexing with [] is just pointer arithmetic in disguise. These two lines produce identical machine code:

C — two ways to write the same thing
arr[2]       // what you write
*(arr + 2)   // what the compiler actually does

The compiler rewrites arr[2] as *(arr + 2) before generating any machine code. The bracket syntax is a convenience. Underneath it is always pointer arithmetic. This also means something that looks bizarre but is completely valid C:

C
printf("%d\n", arr[2]);   // 30
printf("%d\n", 2[arr]);   // also 30 — because arr[2] = *(arr+2) = *(2+arr) = 2[arr]

Addition is commutative. *(arr + 2) and *(2 + arr) are the same. So arr[2] and 2[arr] are the same. It looks insane. It makes complete sense once you see the arithmetic underneath.

arr[i] and *(arr + i) are the same operation
Index i = 2
The compiler rewrites arr[i] as *(arr + i). The bracket is notation. The pointer arithmetic is the reality.

Passing an array to a function

Because an array name is just a pointer to element zero, passing an array to a function means passing that pointer. No copy of the array is made. The function works directly on the original memory.

C
void double_elements(int *arr, int n) {
    for (int i = 0; i < n; i++)
        arr[i] = arr[i] * 2;   // arr[i] is *(arr + i) — modifies original
}

int main() {
    int data[4] = {1, 2, 3, 4};
    double_elements(data, 4);   // passing address of element zero
    printf("%d %d %d %d\n", data[0], data[1], data[2], data[3]);
    // prints 2 4 6 8 — original data changed
}

This is also why you always pass the length separately. The pointer tells you where the array starts. It tells you nothing about where it ends. That is information only the caller has.

Going past the end — what actually happens

Pointer arithmetic is only valid within the bounds of the array it was created from. The CPU has no idea where your array ends. It will happily read or write whatever is at the address you give it.

C
int arr[3] = {10, 20, 30};
int *p = arr;

printf("%d\n", *(p + 2));    // fine — last valid element
printf("%d\n", *(p + 3));    // undefined behavior — one past the end
printf("%d\n", *(p + 10));   // undefined behavior — reading random memory

What happens at that out-of-bounds address depends entirely on what else is in memory at that location. On your STM32 it might read another variable, part of your stack frame, or cause a hard fault if it crosses into a protected region. On Linux it might print garbage silently, or it might segfault. The dangerous case is when it silently prints a plausible-looking value and you never know anything was wrong.

Reading past the end of an array
Index
The CPU does not know where your array ends. Past the boundary you are reading memory that belongs to something else entirely.
The off-by-one error — writing i <= n instead of i < n in a loop — is one of the most common bugs in C precisely because of this. The loop runs one iteration too many, reads or writes past the array, and the program either crashes or silently corrupts data one element over.

NULL — the pointer that points to nothing

There is one special pointer value that appears everywhere: NULL. It is defined as zero and it means this pointer does not point to any valid memory location. It is the conventional way to say "no address."

C
int *p = NULL;    // p exists but points to nothing valid

if (p != NULL) {
    *p = 42;       // only safe to dereference after checking
}

Dereferencing a NULL pointer — doing *p when p is NULL — is one of the most common crashes in C. The CPU tries to access address zero, which is marked invalid by the OS or hardware, and the program terminates. On Linux a segfault. On an STM32 a hard fault.

The habit to build right now: whenever you receive a pointer from somewhere — from malloc, from a function argument — check if it is NULL before using it.

A pointer is a variable that holds an address. The & operator gives you the address of something. The * operator follows a pointer to its destination and reads or writes there. Pointer arithmetic moves by element size, not by bytes. An array name is a pointer to its first element. Everything else in this series builds on these five facts.
