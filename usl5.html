What remains after the first direction

Let us assume we have already done what Blog 4 taught us to do. We took the dataset and chose the best possible direction \(w\). We projected every point onto that direction and reconstructed it from that projection.

This was not a heuristic choice. Among all possible single directions, this one minimized reconstruction error. If our goal was to represent each point using one number, we could not have done better.

But now comes a more subtle question. Is this representation enough to capture the essence of the data.

To answer that, we should not look at the projection anymore. We should look at what was left behind.

For each data point \(x_i\), we approximated it using its proxy on the line spanned by \(w\). The difference between the original point and its approximation is:

\[ r_i = x_i - (x_i^\top w)\,w \]

Earlier, we called this quantity an error. That word makes it sound like a mistake. But it is not a mistake. It is a consequence of choosing to compress.

A better word here is residual.

The residual is what the first direction could not explain. It is the part of the data that remains after we have extracted everything possible along \(w\).

If the dataset were truly one-dimensional in spirit, these residuals would be small or nearly zero. But real datasets are rarely that simple.

When we look at the collection of residual vectors \(\{r_i\}\), we often find structure. The data has not collapsed into noise. It has simply moved into a lower-dimensional subspace.

This observation changes how we should think about the next step. We are no longer searching blindly for another strong direction. We are asking a more precise question.

Given what the first direction has already explained, what is the best way to explain what remains.

Blog 5 begins here. Not by chasing more directions, but by understanding the geometry of the residuals left behind by the first approximation.

What the first direction has already used up

We now have to be honest about what the first direction \(w\) has already done.

When we chose \(w\), we did not choose it arbitrarily. We chose it so that projecting onto it captures as much of the data as possible. That means every component of every point that lies along \(w\) has already been extracted.

Once that projection is done, there is nothing left to gain by looking again in the same direction. Any further attempt to reuse \(w\) would only repeat information we already stored.

This is why it is useful to look at what remains after the projection. For each point \(x_i\), we subtract its best approximation along \(w\). What remains is the residual:

\[ r_i = x_i - (x_i^\top w)\,w \]

Conceptually, this residual is not an error in the sense of a mistake. It is the portion of the point that the direction \(w\) was unable to explain.

Now think about the geometry of this operation. The proxy \((x_i^\top w)\,w\) lies entirely along the direction \(w\). When we subtract it from \(x_i\), we are removing everything that points along \(w\).

That means the residual cannot contain any trace of the direction \(w\). If it did, then the projection was incomplete, which would contradict the fact that we chose the best possible proxy.

In other words, once the component along \(w\) is removed, what remains must lie entirely in directions that are different from \(w\).

We can now make this idea precise with a simple calculation. If we measure how much of the residual lies along \(w\), we find that there is none.

\[ w^\top r_i = w^\top x_i - (x_i^\top w)(w^\top w) = 0 \]

This confirms what the geometry already told us. Every residual vector lies in a space that does not overlap with the direction \(w\).

This observation is not optional. It is a direct consequence of choosing the best possible one-dimensional approximation.

And it has an important implication. If we want to capture more structure in the data, we cannot search for it in directions that overlap with \(w\). We must search in the space where the residuals live.

In the next section, we will ask how to choose the best possible direction inside this residual space, using the same logic we used the first time.

Choosing the next direction from the residuals

At this point, the situation is very clear. We chose a direction \(w_1\), used it to approximate the data, and identified exactly what it failed to explain.

The residuals are not random leftovers. They form a new dataset in their own right. Each residual vector lives in a space that excludes the first direction.

Now ask the same question we asked before, but ask it honestly in this new setting.

If we are allowed one more number per data point, which direction should we choose to best approximate these residuals.

Notice what we are not allowed to do. We are not allowed to reuse the first direction. That information has already been extracted.

So the problem naturally restricts itself. We are no longer searching over all directions in \( \mathbb{R}^d \). We are searching only over directions that live in the residual space.

Within that space, however, nothing has changed conceptually. We still want the direction that captures as much of the residual structure as possible. We still want to minimize reconstruction error.

That means we repeat the same reasoning as before. We look for the direction that best represents the residuals using a one-dimensional proxy.

This produces a second direction, call it \(w_2\). By construction, this direction does not overlap with \(w_1\), because it lives entirely in the space where the residuals live.

And once again, after choosing \(w_2\), we can subtract its contribution and look at what remains.

What is important here is not the notation. What is important is the pattern.

Each step follows the same logic. Choose the best direction for what remains. Remove its contribution. Examine the new residuals.

This process does not require us to invent new ideas at each stage. The same principle of optimal approximation repeats, but in progressively smaller spaces.

In the next section, we will see that this repeated process produces a very specific kind of structure among the directions we obtain, a structure that is not imposed by us, but enforced by the geometry of the problem.

Why the directions do not interfere with each other

By now, a pattern has started to form. We chose a first direction, removed everything it could explain, and then chose a second direction from what remained. We repeated the same logic, without changing the principle.

What is worth noticing is what never happened. At no point did we explicitly demand that the second direction be different from the first. We did not add a constraint saying “do not overlap”. And yet, overlap never appeared.

This is not an accident. It is a consequence of how the residuals were constructed.

The residuals after the first direction live entirely in a space that excludes that direction. When we choose the best possible direction for those residuals, we are choosing from a space that no longer contains the first direction at all.

As a result, the second direction cannot reuse anything the first direction already captured. It is forced to explain something genuinely new.

The same logic applies at every step. After choosing the first two directions and removing their contributions, the remaining residuals live in a space that excludes both. Any third direction chosen from those residuals must avoid the first two as well.

This is how a collection of directions emerges, each one explaining a new aspect of the data, without interfering with what came before.

In geometric terms, these directions end up being perpendicular to each other. Not because we demanded orthogonality, but because reuse would contradict optimality.

If a new direction had any overlap with an earlier one, part of its explanatory power would be wasted on something already accounted for. That would make it suboptimal by construction.

So orthogonality is not a design choice. It is the geometry of optimal compression asserting itself.

By following this process step by step, we naturally arrive at a set of mutually non-interfering directions, ordered by how much structure they explain in the data.

How a single point is explained by multiple directions

So far, we have been talking about directions and residuals at the level of the dataset. But to really understand what is happening, it helps to zoom in on a single data point.

Take one point \(x_i \in \mathbb{R}^d\). When we chose the first direction \(w_1\), we approximated this point by projecting it onto that direction.

\[ \hat{x}_i^{(1)} = (x_i^\top w_1)\,w_1 \]

This approximation captures the part of \(x_i\) that lies along \(w_1\). Everything else is pushed into the residual:

\[ r_i^{(1)} = x_i - \hat{x}_i^{(1)} \]

Importantly, this residual is not arbitrary. It is exactly what remains after removing the component along \(w_1\). There is no ambiguity here.

Now suppose we choose a second direction \(w_2\), not from the entire space, but from the space where the residuals live.

We now repeat the same operation, but on the residual:

\[ \hat{x}_i^{(2)} = (r_i^{(1)\top} w_2)\,w_2 \]

This captures the strongest remaining structure in \(x_i\) that was not already explained by \(w_1\).

After removing this second contribution, we obtain a new residual:

\[ r_i^{(2)} = r_i^{(1)} - \hat{x}_i^{(2)} \]

At this point, the point \(x_i\) has been decomposed into three pieces: one along \(w_1\), one along \(w_2\), and a leftover part that lies outside both directions.

If we continue this process, choosing directions \(w_3, w_4, \dots\), each new direction captures the strongest remaining component of the residual.

After \(k\) such steps, the original point can be written as:

\[ x_i = (x_i^\top w_1)\,w_1 + (x_i^\top w_2)\,w_2 + \dots + (x_i^\top w_k)\,w_k + r_i^{(k)} \]

This expression is not an approximation until we choose to stop. It is an exact decomposition. The only approximation enters when we decide how many directions we want to keep.

Each coefficient \(x_i^\top w_j\) tells us how much of the point lies along the direction \(w_j\). These numbers are the compressed representation of the data point.

The residual \(r_i^{(k)}\) tells us what has not yet been captured. If its norm is small, the point is well explained. If it is large, more directions are needed.

What makes this decomposition particularly clean is the fact that the directions \(w_1, w_2, \dots\) do not interfere with each other. Each direction captures a distinct aspect of the point.

This is the core intuition behind multi-dimensional representation in unsupervised learning. We are not fitting the data to predefined axes. We are letting the data reveal a sequence of directions, each one explaining what the previous ones could not.

What each component is really capturing

Now that we have written a data point as a sum of components along multiple directions, it is important to pause and ask what these components actually represent. Without this understanding, the decomposition remains symbolic.

Consider again the expression we arrived at:

\[ x_i = (x_i^\top w_1)\,w_1 + (x_i^\top w_2)\,w_2 + \dots + (x_i^\top w_k)\,w_k + r_i^{(k)} \]

Each term in this sum plays a very specific role. None of them are interchangeable.

The first component, \((x_i^\top w_1)\,w_1\), captures the most dominant pattern present in the dataset. It tells us how strongly this point aligns with the direction that explains the largest amount of structure across all points.

If you were allowed to remember only one number about this point, the coefficient \(x_i^\top w_1\) would be the most informative choice. Everything else would introduce more error.

The second component, \((x_i^\top w_2)\,w_2\), plays a different role. It does not compete with the first. Instead, it explains the strongest remaining pattern after the influence of \(w_1\) has been removed.

This is why the second direction does not overlap with the first. If it did, it would waste effort re-explaining information that is already accounted for.

As we move to the third, fourth, and subsequent components, the same logic continues. Each new component explains structure that none of the earlier components could capture.

This gives the decomposition a clear interpretation. The components are ordered by importance. Earlier components explain large-scale, dominant variation in the data. Later components explain finer, more subtle structure.

The residual \(r_i^{(k)}\) has a precise meaning as well. It represents everything about the point that remains unexplained after using \(k\) directions. It is not noise by definition. It is simply unresolved structure.

If we choose to stop after a small number of components, we are making a conscious trade-off. We accept some loss in reconstruction accuracy in exchange for a simpler representation.

This is why these coefficients are useful as features. They are not arbitrary projections. They form a coordinate system adapted to the structure of the data itself.

Seen this way, unsupervised learning is not about discovering labels or clusters. It is about discovering directions that successively explain the data, from the most dominant patterns down to the finest details we care to keep.

Where this leaves us

In this blog, we did not introduce a new algorithm. We simply followed the consequences of a choice we had already made.

Once we decided to approximate data using a single optimal direction, it became unavoidable to ask what that approximation failed to explain. That question led us naturally to the idea of residuals.

Residuals turned out to be more than leftover error. They formed a new dataset, living in a space that excluded everything the first direction had already captured. This forced the next direction to explain something genuinely new.

By repeating this logic, we arrived at a sequence of directions, each one capturing a different aspect of the data, and each one avoiding interference with the others.

Looking at a single data point made this structure even clearer. Each point can be decomposed into components along multiple directions, ordered by how much structure they explain, plus a residual that represents what we chose not to store.

At no point did we impose orthogonality or ordering as design choices. They emerged naturally from the goal of optimal approximation.

By the end of Blog 5, we are no longer thinking in terms of raw coordinates. We are thinking in terms of a representation adapted to the data itself, where each number we store has a clear geometric meaning.

In the next blog, we will shift perspective once again. We will look at this same process through the lens of data storage and computation. We will ask how this decomposition changes the way data is stored, and how the matrix viewpoint allows us to compute these representations efficiently.
