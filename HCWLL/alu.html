How Computers Work at the Lowest Level · Topic 4

The ALU: The Calculator at the Heart of Every Processor

You have already built the pieces. An adder. A subtractor. Logic gates. A multiplexer. This topic is about what happens when you wire them all together into one unit and give it a dial.

What the ALU actually is

The Arithmetic Logic Unit is the part of the processor that does the actual computing. Every addition your code performs, every comparison in an if statement, every bit manipulation in a graphics shader, passes through the ALU.

But the ALU is not a single clever circuit. It is a collection of circuits you already understand, wired together with one new addition: a control signal called the operation selector that determines which result reaches the output.

Here is the mental picture. Imagine four calculators sitting side by side. One adds. One subtracts. One ANDs. One ORs. All four are always running, always computing, always producing a result. You have a dial that selects which calculator's display is visible. Turning the dial does not turn the others off. It just changes which one you can see. That dial is the operation selector. The visible display is the ALU output.

Every clock cycle, the processor sets the dial to the right position and reads whatever result appears.

Operation selector

All four operation circuits are always computing. The MUX at the output forwards only the selected result. Switching operations takes one clock cycle because the other results are already ready.

Why everything runs at the same time

This surprises people at first. Why not just activate the circuit you need and leave the rest off?

The answer is time. Switching a circuit on takes time. The signals need to travel through the transistors, charge up the gate capacitances we talked about in Topic 2, and stabilise before you can trust the output. If you had to wait for a circuit to wake up before reading its result, you would be adding delay into every single operation.

By keeping everything running all the time, every result is always ready and stable. The MUX at the output just selects between already-settled signals, which is far faster than waiting for a circuit to spin up.

This is a pattern you will see throughout processor design: spend more transistors to save time. Area is cheap in modern silicon. Clock cycles are not.

The flags: what the ALU tells the rest of the processor

The ALU does not just produce a result. It also produces four single-bit outputs called flags. These tell the rest of the processor something important about what just happened. The processor stores them in a dedicated register called the status register, and almost every branch instruction, every if statement, every loop condition, reads from it.

The flags are computed from the output of the MUX, not from the individual circuits. They describe the result you actually selected, not the results you ignored.

The Zero flag (Z)

Set to 1 if every bit of the result is 0. It sounds simple but it is behind every equality check in every program ever written. When your code says if (a == b), the processor computes a - b and checks the zero flag. If it is 1, the two values are equal.

The hardware to produce it is a single NOR gate across all result bits. NOR gives 1 only when every one of its inputs is 0. For a 4-bit ALU that is a 4-input NOR gate. For a 64-bit ALU it is a 64-input NOR, or more practically a tree of smaller NOR gates. Either way, it is one of the simplest circuits in the whole chip.

The Negative flag (N)

Set to 1 if the result is a negative number in two's complement. From Topic 1 you know that the most significant bit tells you the sign. So the negative flag is literally just a wire connected to the top bit of the result. No gates. No logic. Just a wire. The hardware cost is zero.

The Carry flag (C)

Set to 1 if the addition produced a carry out of the most significant bit. This comes directly from the carry-out wire of the top stage of the adder, the same wire we traced through the ripple carry adder in Topic 3.

For unsigned arithmetic, a carry out means the result was too large to fit in the available bits. If you add two 4-bit numbers and get a carry out, the true result requires 5 bits and the 4-bit output is wrong.

One important nuance: when the ALU performs AND or OR instead of addition, the adder is still running and still producing a carry-out signal. The carry flag gets written with that value, but it is meaningless. The processor knows from the instruction what the last operation was, and it knows to ignore the carry flag after a logic operation. This is a convention defined by the instruction set, not something the hardware enforces.

The Overflow flag (V)

This is the most subtle flag and the one that trips people up most often. The carry flag and the overflow flag both relate to things going wrong in arithmetic, but they mean completely different things.

The carry flag is about unsigned arithmetic running out of bits. The overflow flag is about signed arithmetic producing a mathematically wrong answer.

Signed overflow can only happen in two situations. First: two positive numbers added together produce a negative result. Second: two negative numbers added together produce a positive result. Those are the only cases where the answer can escape the valid signed range. If you add a positive and a negative, the result is always somewhere between them, so overflow is impossible.

The hardware detects this by looking at just three bits: the MSB of A, the MSB of B, and the MSB of the result. If both inputs have the same sign and the result has a different sign, overflow occurred. A small combination of gates on those three bits is all it takes.

Carry vs overflow: the distinction that matters

These two flags describe the same arithmetic from two different perspectives. Carry thinks in unsigned. Overflow thinks in signed. The same bit pattern can trigger one, both, or neither depending on which interpretation you are using.

Each case shows the same addition with both unsigned and signed interpretations. Notice that carry and overflow are independent: either can be set without the other, both can be set, or neither. The processor uses the right flag depending on whether it is doing signed or unsigned arithmetic.

How comparison works without a comparator

There is no dedicated comparison circuit in most ALUs. Comparison is done entirely through subtraction and flags.

To check if A equals B: subtract B from A. If the result is zero, they are equal. Check the zero flag.

To check if A is greater than B for unsigned numbers: subtract B from A. If there was no borrow (carry flag set, in most architectures), A is the larger value.

To check if A is greater than B for signed numbers: subtract and look at the negative and overflow flags together. If they are equal, the result has the correct sign and A is greater. If they differ, overflow flipped the sign and A is actually smaller. This is why the flags exist as a set rather than in isolation.

Every comparison in every high level language compiles down to a subtract instruction followed by a branch instruction that reads one or more flags. The ALU does the arithmetic. The flags carry the answer. The branch reads the flags and jumps or does not jump.

The processor subtracts B from A and reads the flags. There is no comparison circuit. The branch instruction that follows just checks which flags are set. An equality check reads Z. A greater-than check reads N and V together. All of this is done in two instructions and two clock cycles.

The ALU inside the processor

The ALU does not operate in isolation. It sits in the middle of the processor's datapath, connected to the register file on both sides.

When the processor executes an add instruction, here is what physically happens. The register file reads out two values and sends them to the ALU inputs. The instruction decoder reads the binary encoding of the instruction and drives the ALU's operation selector to the correct value. The ALU computes, the MUX forwards the right result, the flags are updated, and the result is written back into a destination register in the register file. The whole sequence happens in one clock cycle.

The ALU does not know what instruction triggered it. It just sees two input values and a selector signal. It computes whatever the selector says to compute and produces an output. The meaning lives in the instruction decoder and the program, not in the ALU itself.

Datapath: how an instruction flows through the processor

Watch the data flow from the register file into the ALU, the operation selector being set by the instruction decoder, and the result being written back. Every instruction that touches the ALU follows this exact path. The ALU is always in the middle.

The ALU has no memory, no history, no awareness of what came before. It sees two numbers and a selector. It computes. That is its entire existence. Everything that makes a computer intelligent comes from the program that decides which numbers to feed it and what to do with the results.
