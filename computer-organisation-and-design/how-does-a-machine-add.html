How Does a Machine Add?

Class 3 ended with a guarantee: anything you can write as a truth table, you can build as a circuit. A guarantee is not a machine. Today the factory produces its first product, and there is only one honest candidate for what that product should be. By the end of this class you will have built, table by table and gate by gate, the circuit that every processor on earth uses to add.

Let me lay out what we own now, because it is more than it feels like. We have gates, physically real, transistors in a tug of war. We have truth tables, and a proof that every truth table can be turned into gates by the minterm recipe: one AND term per 1-row, OR them together, done. We even ran the recipe once, on the majority function of three inputs, and watched it work on all eight combinations.

What we do not have is a single circuit that does anything a person would pay for. The factory is open and the production line is empty. So the question this class starts with is not whether circuits can compute. It is what to build first.

And I think there is only one answer. Every failure in Class 1 was arithmetic going somewhere it should not. The shepherd's pebbles, Pascal's gears, the ENIAC's ring counters, all of them existed to do one thing more reliably than a human hand: count, and combine counts. The machine's oldest job, the job the whole fifty-thousand-year story has been circling, is addition. So we build the adder.

The truth table you cannot write

Start the obvious way and watch it fail, because the failure teaches the most important thing in this class.

Addition is a function on bits. Two 8-bit numbers in, a 9-bit result out. Class 3 says: write the truth table, apply the recipe, collect the circuit. So write the truth table. Two 8-bit inputs means 16 input bits, and 16 input bits means 216 rows. Sixty-five thousand five hundred and thirty-six rows. For 32-bit numbers, the table has 264 rows, a number with twenty digits. Write one row per second and the universe ends first.

The recipe is not wrong. The circuit exists, the proof holds. But a guarantee of existence is not a construction you can carry out, and this is the first time the difference has bitten us. The recipe scales with the size of the table, and the table for wide addition is unwritable.

The way out is not a better recipe. It is a better truth table. And you have known it since you were seven.

Add 47 and 38 on paper. You line the numbers up in columns. Rightmost column: 7 plus 8 is 15, write the 5, carry the 1 as a small pencil mark. Next column: 4 plus 3 plus the carried 1 is 8. Answer 85. Now look at the structure instead of the numbers. You never consulted a giant table of all possible two-digit additions. You processed one column at a time, and every column ran the identical small procedure: two digits in, plus a possible carry from the right, one digit out, plus a possible carry to the left. The only thing connecting the columns was the pencil mark.

That is the escape. Positional notation chops the unwritable table into a small table repeated. The procedure works in any base, because carrying belongs to positional notation, not to base ten. In binary the columns overflow at 2 instead of 10, and nothing else changes.

The same algorithm in two bases — the pencil carry is the only thing moving sideways

So the plan shrinks to something the factory can actually manufacture. Write the truth table of one binary column. Realise it as a circuit. Then copy that circuit once per bit and wire the copies together with the pencil mark. If one column works and the wiring works, addition works, at any width, and we never write the monster table at all.

The smallest circuit worth building

Begin with the easiest column, the rightmost one, which has no carry arriving. Two bits enter. The truth table has four rows and, since 1 plus 1 is 2, which is 10 in binary, it needs two output columns: a sum bit and a carry bit.

Two output columns means two circuits, one per column, sharing the same inputs. Class 3's recipe handles multi-output functions exactly this way.

Now run the process. You could crank the minterm recipe on each output column, and it would work. But look at the columns first, because the factory keeps a catalogue, and checking the catalogue before running the machinery is a habit worth building. The sum column reads 0, 1, 1, 0 down the rows. That is not similar to XOR. It is XOR, the identical truth table from Class 3, row for row. The carry column reads 0, 0, 0, 1. That is AND, exactly.

So the circuit for a carry-free column is two gates we already own, both fed the same two inputs. An XOR produces the sum, an AND produces the carry. No minterms required. Recognition beat construction, and the whole thing has a name: the half adder.

A real column takes three bits

The half adder serves the rightmost column and no other, because every other column receives three things: its two input bits and the carry arriving from the right. Three inputs. The half adder has two. So write the table a real column obeys. Three bits in, each 0 or 1, their arithmetic sum anywhere from 0 to 3, which is 00 to 11 in binary. Two output columns again. Read the Cout column: it is 1 on exactly the rows where two or more inputs are 1. Read the sum column: it is 1 when an odd number of inputs are 1.

Look hard at the carry-out column. It is 1 on the rows 011, 101, 110, and 111. Two or more inputs high. You have seen this function before, and not in passing. It is the majority of three, the exact function we ran the minterm recipe on at the end of Class 3, key by key, lock by lock, and verified on all eight combinations with your own fingers. That worked example was not an example. It was a delivery, arriving one class early. The carry-out circuit of a real adder column is already built and sitting in our catalogue.

The sum column yields to the same recipe. Its 1-rows are 001, 010, 100, and 111, so four minterms, OR them, done. Which means we can stop right here and declare victory on the recipe's terms: a working full column exists, built purely by the Class 3 machinery, no cleverness involved. Existence is settled.

But existence is where engineering starts, not where it ends. Count the hardware the recipe used. Each output column took four three-input ANDs and a four-input OR, plus inverters for the NOTed inputs. Call it a dozen gates and change for one column, and a 64-bit adder needs 64 columns. Before accepting that bill, ask whether the structure of the problem offers something smaller. It does, because a column is secretly two little additions in a row. First add A and B. Then add the carry-in to that result. Each of those is a two-bit addition, and we own a two-gate circuit for two-bit addition. Use two half adders.

The first half adder takes A and B, producing a partial sum s1 and a carry c1. The second takes s1 and Cin, producing the final sum bit and a second carry c2. One question remains: the column's carry-out. A carry happened if either little addition overflowed, so Cout is c1 OR c2. Two half adders and one OR gate. Five gates where the recipe spent a dozen, computing the identical eight-row table. This is the full adder, and it is the most-replicated circuit in your processor.

Set all three inputs to 1 and trace it. The first half adder sees 1 and 1, so s1 is 0 and c1 is 1. The second sees s1=0 and Cin=1, so the sum is 1 and c2 is 0. The OR of the carries gives Cout=1. Sum 1, carry 1, binary 11, three. Three ones in, three out. Work the toggles and the circuit agrees with the eight-row table everywhere, which is the only sense in which a circuit can be correct.

I want to slow down on one detail here, because it looks like luck, and nothing in a good circuit is ever luck. The OR gate merges c1 and c2 as if they could never both be 1 at once, and they never can. If c1 is 1, then A and B were both 1, which forces s1 to 0. And if s1 is 0, the second half adder's carry, s1 AND Cin, is 0 no matter what Cin is. So c1 being 1 guarantees c2 is 0. The two carries are mutually exclusive by construction, which is exactly why a plain OR is enough to combine them. When a refactor is correct, it is correct for a reason you can state.

Chaining the columns

Now the pencil mark becomes a wire. Take one full adder per bit position. Connect each column's carry-out to the carry-in of the column on its left, exactly the way the mark travelled leftward on paper. The rightmost column has no carry arriving, so tie its carry-in to 0. The leftmost column's carry-out pokes out of the end of the circuit, and we will have words about it shortly.

Before you press the button on the widget below, meet the first person who wired this whole arrangement together for real, because he did it with no factory, no catalogue, and no Class 3.

KZ
Konrad Zuse
1910 – 1995  ·  Berlin, Germany
Civil engineer who hated the endless, repetitive structural calculations his job demanded, so he decided a machine should do them. Between 1936 and 1938 he built the Z1, a mechanical binary computer, in his parents' living room, its adder made of sliding metal plates. His Z3 of 1941, built from telephone relays, is widely regarded as the first working programmable computer. He worked in near-total isolation, unaware of Shannon's thesis or Turing's papers, and arrived at binary, chained adder columns, and floating point on his own. He also designed what may be the first high-level programming language, Plankalkül, before any machine existed that could run one.

Zuse's starting complaint is the oldest one in this course: humans doing repetitive arithmetic make errors, and the errors matter. His answer was a machine whose heart was exactly the chain of columns you are about to operate, first cut from metal, then wired from relays, the same two-state switches Shannon was analysing an ocean away at the same moment, neither man knowing of the other. Two people forced independently to the same structure is usually a sign the structure is not an invention so much as a discovery. What you build by following the logic, someone else following the logic will build too.

The chained design is called a ripple carry adder, and the name describes its behaviour honestly. Set two numbers on the inputs and the answer does not appear all at once. The rightmost column settles first. Its carry ripples into the next column, which can only then settle, and its carry ripples onward. The answer flows across the circuit right to left like a wave. Watch it happen.

Run the worst case and pay attention to the order of events. 1111 plus 0001. The only 1 in the second number sits in the rightmost column, yet every single column changes. The rightmost adds 1+1, writes 0, carries. The next column adds 1+0 plus that carry, writes 0, carries again. The carry marches through every position and finally falls out of the left end. Fifteen plus one is sixteen, 10000, five bits.

Then run the no-carries case, 0101 plus 1010. Every column adds a 0 and a 1, no carry is ever generated, and no column's answer ever depended on its neighbour. In that case all four columns could have settled simultaneously. The wave only exists when carries exist.

The price of the ripple

That last observation is the door to something important. In Class 3 I made a point of saying that bitwise AND on a 64-bit register costs the same as AND on one bit, because all 64 gate pairs work in parallel with nothing passing between them. Now you can see exactly what addition loses. Column 5 cannot produce its correct answer until it knows its carry-in, which comes from column 4, which is waiting on column 3, all the way down. In the worst case, the leftmost column of a 64-bit adder is sitting idle until a carry born in column 0 has physically travelled through 63 stages of gates.

Gates are not instant. Each one takes a small but real time to respond to its inputs, a gate delay, and delays in a chain add up. A 64-bit ripple adder in the worst case is a chain of roughly a hundred and thirty gate delays, against the single gate delay of a bitwise AND. Both are fast in human terms. But a processor executing billions of additions per second lives and dies by exactly this kind of accounting, and the ripple adder's carry chain is the slowest path through it.

Engineers did not accept this, and what they did about it is one of my favourite stories in hardware, because it is not one clever fix. It is sixty years of increasingly audacious cheats, each one a different personality's answer to the same slow wire, and every single one of them is still being manufactured today. The ripple adder stays as the design you learn first, because it is the honest one, your pencil algorithm wired up. Everything that follows is people refusing to wait for the pencil.

Bitwise logic is a crowd working in parallel. Addition is a bucket brigade. The bucket is the carry.

Sixty years of attacking one wire

Here is a thing I find genuinely funny about hardware history. The carry chain, this one wire snaking through the adder, became one of the most attacked problems in the entire field. Generations of engineers looked at the ripple adder, felt the same itch you should be feeling right now, and each generation invented a different way to cheat. None of the cheats replaced the others. All of them are still in production somewhere. What follows is the family tree, and for each member I want you to see three things: the problem that forced it into existence, how it actually works, and what it costs. Because every one of these is a trade, and the trades are the interesting part.

And the itch is older than electronics. Charles Babbage hit this exact wall in the 1830s, in brass. His engines did decimal addition with gear wheels, and a carry rippling through thirty digit wheels was agonisingly slow in a machine where every step was a physical rotation. He spent years designing what he called the anticipating carriage, a mechanism that would work out all the carries in advance and apply them in one motion. He never got it built. But the idea, do not wait for the carry, predict it, is the entire second half of this class, sketched a century before the first electronic computer.

First, three words: generate, propagate, kill

Every fast adder ever designed rests on one observation, and it is small enough to fit in a sentence. You can tell what a column will do with a carry without waiting for the carry to arrive.

Look at one column, just its own two bits, A and B. If both are 1, this column will send a carry out no matter what comes in, because 1+1 already overflows on its own. We say the column generates. If exactly one of A and B is 1, the column on its own sums to 1, so it overflows exactly when a carry arrives: whatever comes in goes out. The column propagates. And if both bits are 0, an incoming carry just gets absorbed into the sum, and nothing leaves. The column kills the carry.

Notice what these are in gate terms. Generate is A AND B. Propagate is A XOR B. You already own both of these. They are the half adder's two outputs, wearing new names.

The carry-skip adder: let the boring stretches step aside

The first cheat is the cheapest, and I like how modest it is. It does not try to predict the carry and it does not try to outrun it. It just notices that some parts of the adder are boring, and lets the carry walk around them.

Start from the propagate idea and push it one step further. A single column with P = 1 is completely predictable: whatever carry comes in goes out. It contributes nothing to the carry's story. It is a pipe. Now chop the adder into blocks, say four bits each, and imagine a block where every one of the four columns propagates. The whole block is a pipe. A carry entering it will crawl through four full adders, one slow step at a time, and emerge on the far side exactly as it entered. Four steps of waiting to accomplish, as far as the carry is concerned, absolutely nothing.

So do not make it crawl. Add one AND gate per block that watches the four P signals, and one wire that runs over the top of the block. When the AND fires, meaning the block is all-propagate, the incoming carry takes the wire and jumps the entire block in a single hop. When the AND does not fire, the block contains at least one column that will actually do something to the carry, generate one or kill one, so the carry has to go through and consult it the slow way.

An all-propagate block is a pipe — so give the carry a bridge over it

Before you trust that bridge, prove it holds weight, because a shortcut that changes the answer is not a shortcut. The block's carry-out is, in words, the block generated a carry of its own, OR it propagated the one that came in. Now remember that G and P are mutually exclusive within one column: G is A AND B, P is A XOR B, and no pair of bits can make both true at once. So if all four columns propagate, then not one of them generated, which means the block's own generate is guaranteed to be 0, which collapses the carry-out to a plain copy of the carry-in. The bypass is not an approximation or a lucky guess. In the all-propagate case it is the mathematically exact answer, delivered early. Run it below.

The upper block gets 1111 and 0000, so every column holds exactly one 1, all four P signals are up, and the skip detector fires. The carry arriving from below never enters the block. It takes the bridge, one hop, and lands at the final carry-out. Five steps where plain ripple needed eight.

Eight bits undersells it, so scale the picture. A 64-bit adder chopped into sixteen blocks of four. A carry is born somewhere, ripples out of its birth block the slow way, then hops block to block over every boring all-propagate stretch in the middle, and finally ripples into the block where it gets used up. The worst case has gone from one step per bit to roughly one step per block, and that is a different class of machine.

Now the honest ledger, because this design has real limits and pretending otherwise would waste your time. The speedup depends on the data: a block that is not all-propagate gives you nothing, and the carry still crawls inside the block where it is born and the block where it dies, so those two crawls are a floor no skip logic can remove. The sums inside a skipped block are not free either. The bypass moves the carry-out early, but each skipped block's sum bits still settle by their own internal rippling, which is fine, because when blocks chain, the carry crossing is the thing everyone downstream is waiting for. And even at its best, with block sizes tuned carefully, the worst-case delay grows like the square root of the width, give or take. Genuinely better than ripple's straight line, nowhere near the logarithm the prefix adders will hit at the end of this section.

So why did anyone build it, with lookahead already published? Price. One AND gate and one wire per block is as close to free as hardware gets, against lookahead's exploding fan-in or select's doubled blocks. Carry-skip is what you reach for when you want real speed but you are counting every gate and every microwatt, which is exactly why it kept showing up in low-power and area-squeezed designs long after cleverer adders existed. It is the modest member of the family. It does not predict the carry, it does not compute two futures, it just politely asks the boring stretches to step aside.

The carry-lookahead adder: stop waiting, start predicting

The second cheat is Babbage's dream, finally done in silicon. In 1958, Arthur Weinberger and J. L. Smith at IBM published the design that computes the carries instead of waiting for them, and the reasoning is a chain of plain sentences. When is there a carry into column 1? When column 0 generated. When is there a carry into column 2? When column 1 generated, or column 1 propagated a carry that column 0 generated. Column 3? When column 2 generated, or 2 propagated 1's generate, or 2 and 1 both propagated 0's generate. Every carry unrolls into an expression made only of G's and P's, and G's and P's are available after one gate delay.

So the whole schedule collapses. One gate delay to get every G and P. Two more for the big AND-OR expressions to produce every carry at once. One more for the XORs to produce every sum. Four-ish gate delays, and here is the startling part: that count does not depend on how wide the adder is. The ripple's bucket brigade is gone. Watch the phases fire.

Look at the formulas while you play. C1 has two terms. C2 has three. C3 has four, and C4 has five, each term longer than the last. That growth is the catch. Extend this scheme to 16 bits and the expression for the top carry has seventeen terms, some of them ANDing sixteen signals together, and gates with sixteen inputs are somewhere between terrible and impossible to build. The prediction is free at 4 bits and ruinous at 64.

The fix engineers settled on is the same move we pulled on the giant truth table: impose structure. Build lookahead over 4-bit blocks, then treat each block as a single fat column with its own group generate and group propagate, and run a second layer of lookahead over the blocks. This hierarchical version is what actually shipped, most famously in the 7400-series chips of the 1970s, where a 74181 did four bits of arithmetic and a 74182 did the lookahead across four of them. Sixteen-bit fast addition out of five cheap chips. A whole generation of minicomputers added numbers exactly this way.

The carry-select adder: compute both futures

The third cheat is my favourite, and I will admit that up front, because the trick is so recognisably human. It comes from O. J. Bedrij, also at IBM, in 1962. The upper half of an adder is stuck waiting for one bit of information: the carry coming out of the lower half. One bit. Two possible values. So do not wait. Build the upper half twice. One copy assumes the incoming carry will be 0 and starts immediately. The other assumes 1 and also starts immediately. Both race ahead in parallel with the lower half, and when the lower half finally announces its carry, a multiplexer picks whichever finished answer was computed under the correct assumption and throws the other away.

Carry-select is the middle child of this family: meaningfully faster than ripple, far less wiring madness than full lookahead, and you pay in silicon area. When you do not know something, compute both answers and wait to find out which one you meant. Half the tricks in modern processors, and we will meet the biggest one in the pipeline arc, are this exact idea scaled up.

The parallel prefix adder: the modern answer

The last design is the one inside the machine you are reading this on, and the way it reframes the problem is the kind of thing that makes you put the paper down for a minute. The first time I saw a Kogge-Stone diagram I honestly thought it was a subway map.

Here is the reframe. Forget carries for a second. Take each column's (G, P) pair and define one operation that merges two adjacent stretches of columns into one: a combined stretch generates if the left part generates, or the left part propagates and the right part generates, and it propagates only if both parts do. This merge operation behaves like addition does: you can group it however you like without changing the answer. And any operation with that property can be computed over n items in log₂ n rounds by a trick called doubling. Round one, every column merges with its neighbour, and now every column knows about a stretch of 2. Round two, merge with the result 2 positions away: every column knows a stretch of 4. Round three, distance 4: stretches of 8. Each column's finished stretch tells it directly whether a carry arrives, so all carries, and then all sums, appear together.

Peter Kogge and Harold Stone published this structure in 1973, and Brent and Kung followed in 1982 with a leaner variant. A 64-bit add needs just six merge rounds. Watch eight bits do it in three.

Kogge-Stone's cost is visible in the picture: wires, everywhere, and every one of them switching and burning power. Brent-Kung's variant runs a couple more rounds in exchange for far fewer wires, and the adders in shipping processors are usually hybrids that split the difference, with names like Han-Carlson and Sklansky attached to the blends. Nobody hand-draws these anymore. You write a + b, a synthesis tool weighs your speed, area, and power targets, and it picks a point on this sixty-year menu for you.

So which one is in your laptop?

All of them, honestly, and that is the note I want to end this section on. The ALU's critical path, the adder that has to finish inside one clock cycle billions of times a second, is a prefix hybrid. But an address calculation off in a corner, a counter that only ticks occasionally, a low-power controller sipping from a battery: those are very often plain ripple adders, because ripple is the smallest and stingiest design on the menu and speed is not always the thing being purchased. There is no best adder. There is a menu of trades, and sixty years of engineers have made sure every position on it is occupied.

The bit with nowhere to go

One loose wire is still dangling. The leftmost full adder produces a carry-out, and in a fixed-width machine there is no column to its left. What happens to that bit?

Nothing happens to it. That is the problem. The register is 8 bits, or 32, or 64, and the carry out of the top column simply has no home. Watch it in the widget: 1111 plus 0001 produces a fifth bit. In our toy adder I display it. In a real 4-bit register it would be gone, and the register would read 0000. Fifteen plus one, in a 4-bit machine, is zero.

Now connect this to Class 1, because two of the four stories just became mechanical rather than mysterious. The wallpaper pixel arithmetic produced 271 in an 8-bit channel. 271 needs nine bits. The ninth bit is precisely the top carry-out of an 8-bit adder, and it had nowhere to land. Whether the surrounding code then wraps the value, clamps it, or, as Android found, marches off and crashes on it, the birth of the error is this exact wire. And the 2038 timestamp is not an abstraction either. Somewhere in the machine, once per second, a 32-bit adder computes time plus one. It has been running that same circuit since 1970, and it is carrying its way steadily toward the top of the register.

But notice I said the timestamp will land in 1901, not zero. A wrapped adder should give zero, or something near it. Negative 1901-ness is stranger than a wraparound. The explanation is that the top bit of that register is not an ordinary column at all. It carries a meaning we have not built yet.

The open question
The factory shipped its first product. We can add. But ask this machine to compute 7 minus 5 and it has nothing, because there is no minus sign anywhere in it, only bits. Yet real processors subtract billions of times a second, and almost none of them contain a subtractor circuit. The trick is to turn subtraction into addition, and the trick requires an answer to a question we have been walking past since Class 2: what is a negative number in binary? Answer that, and subtraction comes free from the adder you built today, and the 2038 timestamp's plunge to 1901 stops being strange. That is Class 5.

Keep the image of the ripple in your head as we go. Every arithmetic circuit we build from here on is this adder wearing different clothes. Subtraction will be this adder with a twist on one input. Multiplication, in Class 7, will be this adder used repeatedly. Class 3 promised that every truth table is a circuit. Today we cashed the first cheque, watched sixty years of engineers argue about the bill, and found out the pencil mark you learned at seven is one of the load-bearing ideas of the century.
