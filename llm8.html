1. A New Question: Where Do These Probabilities Come From?

In the previous chapter, we finally introduced the idea of probability:

p(context | center) = “How likely is this context to appear next to this center?”

We said that our model computes this probability using softmax:

p(context | center) = escore(center → context) / Σall c' escore(center → c')

This is the model’s probability. But… probability of what? Where does the true probability — the one we are trying to match — actually come from?

We were never given any “true probability tables”. No teacher handed us:

  • p(I | love)
  • p(my | love)
  • p(dog | love)
  • etc.

And yet, our training objective says we must maximize these probabilities. So the natural question is:

Where does the true probability distribution come from?

This chapter is about showing that this distribution is hidden in the training data itself, and our model is simply trying to approximate it.

2. The Secret: The Training Corpus Already Contains a Probability Distribution

Let’s return to our four-sentence universe:

I love my dog.
I love my cat.
You love my dog.
You love my cat.

When we extract all (center → context) events from these sentences, we are not just forming a list — we are forming empirical statistics. These statistics implicitly contain a probability distribution.

Let’s look at just the events where the center is:

center = love

From the corpus, we saw:

  • love → I (twice)
  • love → You (twice)
  • love → my (four times)

Nothing else occurs as context for “love”.

So the empirical distribution — the true distribution according to our data — is:

pdata(I | love) = 2 / 8
pdata(You | love) = 2 / 8
pdata(my | love) = 4 / 8

And:

  • pdata(dog | love) = 0
  • pdata(cat | love) = 0

We did not invent these numbers. We did not assign them arbitrarily. They were already there, encoded in how often things appear in the training data.

The corpus already contains a probability distribution. We are simply uncovering it.

3. The Fundamental Goal of Training

Now, the goal of training becomes beautifully clear:

We want the model’s probability pmodel(context | center) to match the empirical probability pdata(context | center)

This is the entire purpose of learning W and C. All the geometry, dot products, exponentials, softmax — everything is there to allow us to shape W and C so that:

pmodel(context | center) ≈ pdata(context | center)

When this match is perfect, our embeddings encode the true structural relationships present in the dataset.

4. How the Model Tries to Match the Data Distribution

Our model computes:

pmodel(context | center) = eW[center]·C[context] / Σ eW[center]·C[c']

Compare this to:

pdata(context | center) = (count of (center → context)) / (total events with center)

The model tries to adjust W and C so that these two probabilities line up. Let’s walk through this slowly and intuitively.

4.1. If the data says a context is common…

For example:

pdata(my | love) = 4/8 = 0.5

Half the time “love” appears, “my” is next to it. So our model should behave such that:

pmodel(my | love) ≈ 0.5

To achieve this, the model will:

  • increase score(love → my)
  • increase escore(love → my)
  • thus increase pmodel(my | love)

4.2. If the data says a context is rare…

For example:

pdata(dog | love) = 0

Then the model must eventually push:

pmodel(dog | love) → 0

To do this, the model must make:

  • score(love → dog) very low
  • so that escore is tiny
  • so that softmax assigns it negligible probability

This is the meaning of the “negative pressure” during training: events that never occur in the dataset get pushed down.

5. An Intuitive Picture: The Training Set Is the Teacher

Think of the training set as a tutor that keeps giving hints:

  • “love and my appear together a lot.”
  • “love and dog never appear directly next to each other.”
  • “I and You behave symmetrically around love.”
  • “dog and cat behave symmetrically around my.”

The tutor never says:

  • “p(my | love) = 0.5”
  • “p(I | love) = 0.25”

Those probabilities are not written anywhere explicitly. They are hidden inside the dataset, waiting to be discovered.

Training is the process of making the model uncover these hidden probabilities and match them with its own predicted probabilities.

The model searches for W and C such that:

  • common events get high model-probability,
  • rare events get low model-probability,
  • impossible events get probability near zero.

6. Formalizing the Goal: Matching Two Distributions

For each center word w, the data defines a distribution:

pdata(context | w)

And the model defines a distribution:

pmodel(context | w)

The objective of training is:

Choose W and C to make pmodel(context | w) as close as possible to pdata(context | w).

When these two distributions match closely, we say the model has “learned the statistics of the language”. This means:

  • Words that co-occur often end up geometrically aligned.
  • Words that play similar roles end up near each other.
  • Words that never meet end up far apart.
The training set’s distribution → becomes the model’s distribution → becomes the geometry of the embedding space.

7. The Beauty of the Whole Design

Let’s pause and appreciate the architecture:

  1. The dataset implicitly contains probabilities through word co-occurrence counts.
  2. We extract these through repeated (center, context) events.
  3. We define scores from word vectors W and C.
  4. We convert scores to strengths using ex.
  5. We convert strengths to probabilities using softmax.
  6. We adjust W and C so these probabilities match the hidden data distribution.
Training is simply the correction loop that pushes pmodel(context | center) → pdata(context | center).

Once this match becomes good, the embedding matrices W and C naturally encode the structure of the corpus. When this happens, meaning emerges in geometry.

8. Where We Go Next: Loss

We now understand:

  • the dataset defines a hidden probability distribution,
  • the model defines a probability through softmax,
  • and training aims to make these match.

The next question is:

How do we measure “match” mathematically, and how do we force the model to improve it?

This is the purpose of the loss function. In the next chapter, we will derive — naturally and slowly — why the log-likelihood of the data leads to the famous cross-entropy loss, and how it pushes the model to increase the probability of true events.
